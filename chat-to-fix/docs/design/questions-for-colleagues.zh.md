# 自动修复 Bot：需要问同事的问题

- 日期：2026-11-11
- 用途：下面两段可以直接发出去。消息一给负责 Slack 和 Jira 接入的同事；消息二给决定试点范围和 GitLab 权限的同事。
- 这些答案从开工第 3 天起要用（见 [kickoff-plan.zh.md](kickoff-plan.zh.md) 第 7 节）。
- 2026-11-12 注：真实的 Slack、Jira、GitLab 适配器和一个 Slack Socket Mode 转发程序已经按公开 API 写好（见 spec-4），没有等这些答案。这些问题仍可用来和同事核对接法和权限。

## 消息一：给负责 Slack 和 Jira 接入的同事

你好，我在做自动修复 bot 里“收到任务以后怎么干活”的部分：收到 Slack 里的 @ 之后，建 Jira 单、改代码、开 Draft MR。Slack 和 Jira 的接入在你这边，想和你对齐接口。下面的问题麻烦回复，简短即可。

**Slack 事件怎么到我这边**

1. Slack 应用接收 @ 用的是 Events API（需要一个公网回调地址），还是 Socket Mode？
2. @ 事件是你那边的服务收到后转给我（HTTP POST 到我的监听端口），还是由我这边直接订阅？
3. 试用阶段我的服务跑在我自己的 Mac 上。事件怎样能到我的机器？
4. 转给我的事件里能带哪些字段？我需要：事件编号（用来去重）、频道编号、讨论的 `thread_ts`、消息的 `ts`、发起人的用户编号和显示名、消息文字、附件列表。
5. Slack 重复投递同一个事件时，事件编号保持不变吗？

**读讨论和回消息**

6. 我需要读发起 @ 的那个讨论里的全部消息。是你封装成接口给我调，还是给我 bot 令牌，我自己调 `conversations.replies`？这个令牌现在有哪些权限范围？
7. 在讨论里回复由谁发？如果由我调，用哪个 bot 身份、哪个接口？
8. 哪些人可以通过 @ 触发？有没有名单？

**Jira**

9. bot 建单用哪个 Jira 项目、哪种类型？有哪些必填字段和标签？
10. 建单、加评论、改状态用哪个账号？是你封装成接口，还是给我凭证？
11. 允许 bot 把单改到哪些状态？
12. 现有的自动化规则“工单进入 In Progress 且标题带 [AI-fix] 前缀时，调用 Rovo 的 F2P Jira Fix Agent”还在启用。新 bot 建的单怎样才不会同时触发它？两套流程并存时怎么区分？

**联调**

13. 有没有测试用的频道？什么时候可以联调？

## 消息二：给决定试点范围和 GitLab 权限的同事

你好，自动修复 bot 的方案已经定了（Slack 里 @ 之后自动建 Jira 单、改代码、开 Draft MR，不合并、不批准）。开工前需要你定下面几件事：

1. 试点用哪个 Slack 频道？对应哪个 GitLab 仓库（项目编号、路径、默认分支）？
2. 频道、仓库、Jira 项目三者的绑定关系记在哪里，由谁维护？
3. bot 推分支、开 MR 用哪个 GitLab 账号？需要一个带 `api` 和 `write_repository` 权限的令牌。
4. 分支命名沿用现有的 `ai/<Jira 单号>` 吗？MR 的目标分支是默认分支吗？要不要加评审人或标签？
5. 这个仓库的保护规则允许该账号推新分支吗？
6. bot 只开 Draft MR，不合并、不批准、不关闭。这个边界符合要求吗？
7. 试用阶段跑在我的 Mac 上，一次只处理一个任务。正式部署的机器什么时候能有？它需要能访问 Anthropic API、公司 GitLab、Slack 和 Jira。
