# 运行记录

每次用 Agent 实际跑一遍 `/fix`，在这里记录走过的步骤、结果和卡点。同一轮多用例回归可以合并为一份记录。重点留下**跑通的流程**，以后照着复现；没跑通的也记，写清卡点和归属。

分工：这里记每次运行的过程；确认的问题另外在 [`docs/issues/`](../../issues/README.md) 单独成文，运行记录里链接过去。

## 文件怎么起

- 单次任务文件名：`<日期>-<任务号>.md`，例如 `2026-11-13-T-3.md`。任务号是 Agent 给的 `T-n`，数据目录清空后会从 1 重来，所以前面加日期。
- 多用例回归文件名：`<日期>-<代码提交>-manual-regression.md`。一轮回归用一个文件，并为每个用例分别记录结果和证据目录。
- 同一个问题改好后再跑，记新文件，在旧文件末尾写“后续：见某某文件”。
- 不写 token、密钥和个人凭据；Jira 单、MR、流水线链接可以写。

## 每个文件写什么

1. **一句话结果**：跑通 / 卡在第几步，以及原因。
2. **环境**：Agent 代码版本（分支和提交号）、模型路线（API key 还是 Claude Code）、入口（模拟页面还是真 Slack）、数据目录是否新建。
3. **输入**：`/fix` 的原文。
4. **步骤表**：时间（北京时间）、步骤、结果、产物（Jira 单、分支、MR、流水线）。
5. **卡点和原因**：已核实的写证据（日志原文、代码位置），没核实的标“推断”。
6. **花费和用时**。
7. **清理**：测试产生的 Jira 单、MR、分支要不要关、谁来关。
8. **原始数据**：记录里的事实都从 Agent 的任务记录取，写明在哪、摘了哪些字段。

## 原始数据在哪

Agent 把每个任务的全程状态记在数据目录里（`npm start` 默认是 `src/chat-to-fix/.data/connected/`）。这些文件只在跑的那台机器上，不进 git；数据目录清空后任务号从 T-1 重来，所以要在运行记录里摘出关键值。

| 来源 | 内容 |
| --- | --- |
| `<数据目录>/tasks/T-<号>/task.json` | 任务当前状态：`jira`（单号、链接）、`repo`（分支、基准提交 `base`）、`mr`（链接、`iid`、当前提交 `sha`）、`ci`（等的提交、第几轮、流水线链接、失败 job、结果、停下的原因、等了多久 `waitedMs`）、评审结论、发起人原文、每轮运行、花费 |
| `<数据目录>/tasks/T-<号>/records.jsonl` | 执行记录：每个 bot 每次调用工具、每一步推进、每次 CI 变化各一行，查问题用 |
| `<数据目录>/tasks/outbox.jsonl` | 发给 Slack 的每条消息；所有任务共用一份，按 `taskId` 筛 |
| `GET /tasks/T-<号>?records=1`（带 `x-chat-to-fix-token`） | 一次拿到 `task.json` 和执行记录 |
