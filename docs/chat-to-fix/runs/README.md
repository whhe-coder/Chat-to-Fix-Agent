# 运行记录

每次用 Agent 实际跑一遍 `/fix`，在这里记一个文件：走了哪些步骤、每步的结果、卡在哪、原因是什么。重点留下**跑通的流程**，以后照着复现；没跑通的也记，写清卡点和归属。

分工：这里记每次运行的过程；确认的问题另外在 [`docs/issues/`](../../issues/README.md) 单独成文，运行记录里链接过去。

## 文件怎么起

- 文件名：`<日期>-<任务号>.md`，例如 `2026-11-13-T-3.md`。任务号是 Agent 给的 `T-n`，数据目录清空后会从 1 重来，所以前面加日期。
- 一次运行一个文件。同一个问题改好后再跑，记新文件，在旧文件末尾写“后续：见某某文件”。
- 不写 token、密钥和个人凭据；Jira 单、MR、流水线链接可以写。

## 每个文件写什么

1. **一句话结果**：跑通 / 卡在第几步，以及原因。
2. **环境**：Agent 代码版本（分支和提交号）、模型路线（API key 还是 Claude Code）、入口（模拟页面还是真 Slack）、数据目录是否新建。
3. **输入**：`/fix` 的原文。
4. **步骤表**：时间（北京时间）、步骤、结果、产物（Jira 单、分支、MR、流水线）。
5. **卡点和原因**：已核实的写证据（日志原文、代码位置），没核实的标“推断”。
6. **花费和用时**。
7. **清理**：测试产生的 Jira 单、MR、分支要不要关、谁来关。
