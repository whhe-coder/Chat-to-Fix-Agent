# 其他频道只发 `/fix` 时先提示用法，而不是提示去指定频道

- 状态：已修复 by commit `3cc4cb8`（#20）；2026-11-14 真实 Slack 复测通过
- 发现日期：2026-11-14
- 关联：真实 Slack 测试，不产生任务

## 复现

1. 在指定频道以外的频道只发 `/fix`（不带正文）。
2. 按提示补上正文再发一次。

## 现象与证据

第 1 步收到用法提示 `用法：/fix 问题描述……`；第 2 步才收到 `请在指定频道里用 /fix。`。用户要发两次才知道这里不能用。

[spec](../../spec/slack-fix-command.md) 的处理表先判“正文为空”，再判“在私信或其他频道里用”；[`fix-command.js`](../../src/slackBot/fix-command.js) 的 `handleFix` 按同样顺序实现。

两种情况都在 Bot 里拦下，只回发起人一条临时消息，不调 Agent 的 `/health`，Agent 没有收到请求（测试后没有新任务，发件箱没有新增）。

## 验收

- [x] 先判频道，再判正文为空：其他频道里不管有没有正文，都回 `请在指定频道里用 /fix。`。
- [x] spec 表格调整顺序。
- [x] 补单元测试：其他频道 + 空正文 → 提示去指定频道。

## 复测（2026-11-14，#20 合并后）

在指定频道以外的频道只发 `/fix`，直接收到 `请在指定频道里用 /fix。`，没有先回用法。Bot 在本地拦下，不产生任务，所以没有发件箱或任务记录，结果是在 Slack 界面上看到的。
