# 信息不足时“补充后重新 /fix”的提示重复，追问挤在一行

- 状态：已修复 by commit `92584ca`（#23，Agent）和 `3cc4cb8`（#20，Bot）；真实 Slack `T-9` 复测通过
- 发现日期：2026-11-14
- 关联任务：真实 Slack `T-6`、`T-7`（均没建单）；复测 `T-9`（没建单）

## 复现

1. 在 `#ai-intern-logan-team` 发一条描述不清的命令，例如 `/fix 登录页有问题，用不了`。
2. 看频道里的任务消息和它的讨论串。

## 现象与证据

用户依次看到 4 条消息（T-6，发件箱第 21–23 条加 Bot 的任务消息）：

| # | 位置 | 内容 | 谁发 |
| --- | --- | --- | --- |
| 1 | 频道 | `<@发起人> 提交了修复请求：登录页有问题，用不了`，第二行 `要补充或修改，请重新 /fix 并写完整描述。` | Bot，[`fix-command.js`](../../src/slackBot/fix-command.js) 的 `FOLLOW_UP_HINT`，文案按 [spec](../../spec/slack-fix-command.md) |
| 2 | 讨论串 | `收到，开始处理。` | Agent，[`slack.md`](../../src/chat-to-fix/core/prompts/slack.md) 第 1 步的 `ack` |
| 3 | 讨论串 | `你说的"登录页有问题，用不了"具体是什么情况？请补充：1) 现象……2) 复现步骤；3) 环境……4) 期望的结果。`（整段一行） | Agent，模型按提示词生成 |
| 4 | 讨论串 | `任务 T-6 缺的信息补全后，请用 /fix 重新提交（把原来的描述和补充一起写上）。` | Agent，[`monitor.ts`](../../src/chat-to-fix/core/task/monitor.ts) 的 `needs_info_resubmit` |

T-7（`/fix README 要改一下`）同样是这 4 条。

## 影响

- 第 1、4 条各说一次“重新 /fix”，第 3 条又让用户补充。第 1 条在 Agent 判断之前就出现，每个任务都有，用户会以为自己写得不对。
- 第 1 条叫用户补充，第 2 条又说开始处理，随后第 3 条说信息不够，前后矛盾。
- 第 3 条的几个要点挤在一行，不好扫读。

保留提示的原因仍然成立：Slack 消息事件已关闭，Bot 读不到讨论串里的回复，补充只能重新 `/fix`。

## 验收

- [x] Bot：任务消息只写 `提交了修复请求：<原文>`，去掉 `FOLLOW_UP_HINT` 这一行；spec 表格同步。（#20）
- [x] Agent：追问分行列出要补充的项，和 `needs_info_resubmit` 合成一条；结尾说明讨论串里的回复收不到，请重新 `/fix` 并写上原描述和补充。（#23）
- [x] 用真实 Slack 复测一次，信息不足时讨论串只有“收到”和一条追问。（T-9）
